# Vending-Machine AI Agent + On-Chain TaskRegistry

Sandbox extension on top of the Stanford Generative Agents framework. The
vending machine `Vendy Unit-001` lives in **Central Plaza** alongside three
fully-cognitive customer personas. Every business action Vendy takes is
recorded on chain in `TaskRegistry.sol` (two-tier: HOURLY parents, ACTION
children).

For the design rationale, scope, risks, and verification path see
[`/root/.claude/plans/ai-agent-taskregistry-golden-kahan.md`](.).

## Layout

```
contracts/                              # Foundry project (TaskRegistry.sol)
reverie/backend_server/
  blockchain/                           # Web3 client / mock / async queue / journal
  vending/                              # business state, event bus, transactions, registry adapter
  persona/cognitive_modules/plan.py     # patched: emits hourly_*/action_* events to vending.events.bus
  reverie.py                            # patched: mounts VendingState + wires TaskRegistryAdapter
environment/frontend_server/storage/
  base_vending_min/                     # Vendy + 3 customer personas, plaza_world meta
environment/frontend_server/static_dirs/assets/vending/
  matrix/                               # generated by scripts/build_maze.py
scripts/
  build_maze.py                         # regenerate the plaza maze CSVs
  build_plaza_tilemap.py                # regenerate the Tiled JSON for Phaser
  seed_embeddings.py                    # seed bootstrap_memory thoughts (stub or OpenAI)
  devchain_up.sh                        # start anvil
  deploy_local.sh                       # forge deploy + write .env.local + export ABI
  replay_journal.py                     # reconcile a stale journal against chain
  e2e.sh                                # one-shot smoke
tests/                                  # pytest: bus -> adapter -> mock client + maze + tilemap + seeder
```

## Quickstart

```bash
# 1. Run the unit tests (no chain needed; uses MockTaskRegistryClient).
pytest tests/ -q

# 2. Start anvil + deploy.
bash scripts/devchain_up.sh
bash scripts/deploy_local.sh           # writes .env.local + exports ABI

# 3. Build the plaza maze CSVs.
python scripts/build_maze.py

# 4. Run the sim with the vending template.
bash scripts/e2e.sh                    # interactive: enter base_vending_min
```

## Known gaps

- **Phaser frontend visualization** — addressed in v1: a generated Tiled
  JSON lives at `assets/vending/visuals/plaza.json` and `home/main_script.html`
  picks the right tilemap based on `meta.json:maze_name`. Tileset PNGs are
  reused from `the_ville/visuals/`. Game-object sprites are stand-ins; for a
  proper plaza look, swap `obj_gid_map` in `scripts/build_plaza_tilemap.py`.
- **Embedding seeds for personas** — addressed in v1 via
  `scripts/seed_embeddings.py`. By default it writes deterministic stub
  vectors (md5-seeded, unit-norm); pass `--online` (with `OPENAI_API_KEY`)
  to use real `text-embedding-ada-002`. Vendy's 6 seed thoughts live at
  `personas/Vendy Unit-001/seed_thoughts.json`.

## Live dashboard (index.html ↔ /api/vending)

Repo-root `index.html` is a self-contained dashboard. It runs in two modes:

- **Playground** (default): rule-based microsim, fully in-browser, persists to
  `localStorage`. No backend required. Good for showing the economic model.
- **Live**: dashboard pulls real data from a running Django sim via three
  read-only endpoints. Click the `Live` button next to the economy toggle,
  paste the `sim_code`, and it polls every 1.5s.

Endpoints (all rooted under `environment/frontend_server/`):

| URL                                       | Returns                                             |
|-------------------------------------------|-----------------------------------------------------|
| `/api/vending/state/<sim_code>/`          | `vending_state.json` + maze_name + curr_time        |
| `/api/vending/journal/<sim_code>/?since=N`| Tail of `blockchain_journal.jsonl` from offset `N`  |
| `/api/vending/personas/<sim_code>/`       | Latest `environment/<step>.json` + per-persona role |

In Live mode `index.html` overrides:
- `economy.stock` ← `vending_state.inventory`
- `economy.prices` ← `vending_state.prices_cents / 100`
- `economy.operatorCash` / `economy.revenue` ← `cash_balance_cents / 100`
- `economy.health` ← `power_pct`
- `vendingAgent.auditTrail` ← rebuilt from journal entries (kind →
  status: `tx_*` → committed, `intent_fail` → failed, `intent_*` → queued)
- `agents` ← persona positions, role-coloured

The rule sim is paused in Live mode so it doesn't fight the backend feed.
Toggling Live off restores the playground.

## Per-persona model routing

`reverie/backend_server/vending/model_router.py` monkey-patches
`openai.ChatCompletion.create` to honor a thread-local persona role. Vendy
runs on `MODEL_VENDY` (default `gpt-4o`); customer personas run on
`MODEL_CUSTOMER` (default `gpt-4o-mini`). The patch is installed once at
sim start; `reverie.py` wraps each `persona.move(...)` in `with_persona(p)`
so any nested LLM call picks the right model.

To override the choice, export env vars before launch:

```bash
export MODEL_VENDY=gpt-4o
export MODEL_CUSTOMER=gpt-4o-mini
```

## Modes

`BLOCKCHAIN_MODE` controls the client wiring (default `mock`):

| mode    | RPC | Tx submitted | Use for |
|---------|-----|--------------|---------|
| `live`  | yes | yes          | anvil / testnet |
| `mock`  | no  | no           | unit tests, CI |
| `dryrun`| no  | no, journal-only | local sim with no chain available |
